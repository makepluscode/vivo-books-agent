# 고정 경로 vs Liner 에이전트 — 실험 기록 (2026-11-22)

> 이 문서는 2026-11-22에 이전 목업(실제 출간 도서 구조를 본뜬 원고)과 비공개 저장소로 한 실험 기록이에요. 지금 데모는 새로 쓴 가상 기술서([`sample-book/`](../sample-book/))와 공개 저장소의 실제 개정 PR [vivo-books-sample-book#2](https://github.com/makepluscode/vivo-books-sample-book/pull/2)예요.

요약: **개정 흐름 7/7 · 장 점검 27/27(블라인드 11/11 포함)**. 같은 Liner 에이전트를 데모와 장 점검의 주 경로로 써요.

입력: 실제 출간 도서 7장 구조를 본뜬 목업 원고(`samples/living-langchain/chapter07.md`).
`Tool`·`create_react_agent`·`AgentExecutor`를 쓰고, 목표 환경(LangChain 1.5.0)에서 `ImportError`로 멈추는 예제예요.
검증 계약은 두 경로가 같아요. 세 도시 출력, 실제 도구 호출, 도구 응답 변경 반영, 인용 구절 대조를 모두 통과해야 반영돼요.

- 원자료: `out/exp/*`(로컬, git 제외). 요약 표: [`experiments/drift-agent/results-2026-11-22.md`](../experiments/drift-agent/results-2026-11-22.md). 요약 스크립트: [`experiments/drift-agent/summarize.py`](../experiments/drift-agent/summarize.py)
- 비용: Liner 잔액 $194.58 → $193.63, **실호출 12회에 총 $0.96**

레거시 호환 패키지(`langchain_classic`)를 고른 실행은 한 번도 없었어요.

## 관찰

1. **에이전트는 제출 전에 스스로 시험해요.** `run_example`을 1~4번 돌린 뒤 제출했고, 하네스가 제출을 거절한 적은 없었어요.
2. **실제 라이브러리 오류에 적응했어요.** agent-1의 첫 후보는 `langchain_core.tools.Tool`로 감싼 도구였는데, LangChain과 Python 3.14 조합에서 `NameError: name 'uuid' is not defined`가 났어요. 하네스 밖에서도 똑같이 재현되는 실제 오류예요. 에이전트는 이 오류를 보고 `@tool` 함수를 바로 넘기는 방식으로 바꿨어요.
3. **하네스가 검증 우회 시도를 막았어요.** agent-1이 `inspect.getsource(vivo_demo)`로 검증 픽스처를 읽으려 했어요. import 정책이 막았고(`예제 범위 밖의 import예요`), 에이전트는 정상 경로로 돌아갔어요.
4. **설정 없이도 동작해요.** 고정 경로는 장마다 사람이 적은 검색어(`search_queries`)와 공식 도메인(`official_hosts`)이 있어야 해요. 에이전트는 오류 메시지를 보고 검색어를 직접 만들고, 공식 출처는 목표 환경 패키지 메타데이터(Project-URL)에서 정해요. 예를 들면 `docs.langchain.com`, `reference.langchain.com`, `github.com/langchain-ai/langchain`이에요.
5. **라우팅:** `liner-claude-router`는 이 과제를 매번 claude-opus-5.5로, `liner-gpt-router`는 gpt-6.2-astra로 보냈어요. GPT 쪽이 약 2배 빨랐지만, 이 모델은 2026-11-22 가격 문서에 없어 비용을 따로 계산하지 못했어요.

## 선정: 데모 주 경로 = Liner 에이전트 (`liner-claude-router`)

| 심사 항목 | 에이전트를 고른 이유 |
|---|---|
| Liner 활용 (20) | Router가 도구 호출로 Search를 언제, 어떤 검색어로 부를지 직접 정해요. 필요하면 Search Agent도 불러요. "API를 차례로 부르는 파이프라인"보다 Liner를 더 깊이 쓰는 모습이에요 |
| 확장성 (20) | 장마다 검색 설정을 적지 않아도 돼요. 새 책이나 라이브러리에 붙이는 비용이 줄어들어요(설정 없는 장 실험) |
| 완성도 (30) | 시험 → 실패 → 수정 → 검증 통과 과정이 기록으로 남고 리더에서 보여요. 우회 시도도 하네스가 막아요 |

비용과 위험:
- 장 1회에 Router 비용 약 $0.08~0.17이 들고, 고정 경로보다 느려요(30~47초).
- 실행마다 탐색 순서가 달라요. 데모와 영상은 agent-1 실호출 기록을 **캐시로 재생**해서 같은 결과를 보여줘요(`--offline`).
- 고정 경로는 그대로 남겨 둬요. 여러 항목을 점검하는 장 점검(`drift.pipeline`)과 비교·대체 경로로 써요.

## 2차 — 같은 에이전트로 장 점검(여러 항목) 정답지 평가

에이전트 엔진(`Session`)을 공통으로 만들고, 장 점검 항목 하나를 판정하는 작업(`agent.inspect_item`)을 붙였어요(`python -m drift <원고> --agent`).
정답지는 그대로 썼어요(모델에 보내지 않음). 세 장 모두 **같은 최종 코드**로 측정했어요.
원자료와 채점 출력은 [`experiments/drift-agent/inspect-results-2026-11-22.md`](../experiments/drift-agent/inspect-results-2026-11-22.md)에 있어요.

| 원고 | 라이브러리 | 고정 경로(11/17) | **에이전트** | 오탐·지어냄 | 인용 원문 일치 | 장 1회 |
|---|---|---|---|---|---|---|
| `chapter03` 개발용 | LangChain·OpenAI·pandas·PyTorch·ROS 2 | 8/8 | **8/8** (+보너스) | 0 · 0 | 7/7 | 92초 (고정 96~112초) |
| `chapter05` 홀드아웃 | numpy·scikit-learn·pydantic·matplotlib·requests | 8/8 | **8/8** | 0 · 0 | 10/10 | 48초 (고정 113초) |
| `chapter07` **블라인드** | numpy·SciPy·Pillow·NetworkX + 내부 SDK | 11/11 | **11/11** | 0 · 0 | 13/13 | 53초 (고정 109초) |

도구 사용(30항목): Liner Search 28회, Search Agent 1회, 수정안 격리 실행 13회, 판정 제출 31회(하네스 거절 1회).
판정 근거: 공식 문서 인용 21건, 목표 환경에서 관측한 실패 1건(pip 고정 설치), 근거 불필요(GREEN·UNKNOWN) 8건.
수정안 18개: 끝까지 실행 11 · 외부 연결 직전까지 3 · 앞 절 문맥 필요 1 · 문장 수정 3.

**이 과정에서 찾아 고친 하네스 문제 3가지**
1. **pip 설치 확인이 깨져 있었어요.** 목표 환경의 `pip` 스크립트 shebang이 지워진 이전 작업 폴더를 가리켜서, 폴더를 옮긴 뒤 설치 확인이 `FileNotFoundError`로 실패했어요. 이제 `python -m pip`으로 불러요.
2. **관측된 실패도 근거로 인정해요.** 고정 버전 설치가 목표 Python에서 실패한 것을 하네스가 직접 관측했는데도, 공식 웹 문서 인용이 없다는 이유로 RED를 거절하고 있었어요. 이제 실행·설치 실패로 뒷받침되는 RED는 인용 없이도 받고, 판정 근거(`evidence_basis`)를 기록해요. YELLOW는 여전히 공식 인용이 필요해요.
3. **네트워크가 필요한 수정안을 실패로 잘못 분류했어요.** `load_boston` 대체안(`fetch_openml`)은 격리 환경에서 네트워크가 막혀 `URLError`로 멈춰요. 이건 외부 연결 직전까지 실행된 경우(`needs_api`)로 분류해야 해요. 고친 뒤 수정안이 유지됐어요.

비용: 장 1회 약 $0.37(고정 경로 약 $0.29). 2차 실험은 장 단위 실호출 7회에 $2.62였어요(잔액 $193.63 → $191.01).

## 3차 — 3장짜리 책 전체 개정 (4·7장 동시)

목업 책에 실제 도서 4장 구조의 프롬프트 템플릿 예제를 넣었어요(`langchain.prompts` → 1.x에서 import 실패).
검증기는 장마다 계약을 선언하도록 일반화했어요. 7장은 기존 에이전트 흐름 검사를 쓰고, 4장은 새 `stdout` 계약을 써요.
`stdout` 계약은 기대 출력, 함수 검사, 숨은 무작위 입력이 답에 반영되는지를 확인해요. 입력을 무시하고 하드코딩한 답은 거절돼요.

| 실행 | 결과 | 책 1회 | 4장 수정 | 7장 수정 |
|---|---|---|---|---|
| 에이전트 6회 (7장 캐시 재사용 3회 + 전부 새로 3회) | **6/6** r2 EPUB 생성 | 34~63초 | import 한 줄(`langchain_core.prompts`) + 설명 문단 | `create_agent` 재작성 |
| 고정 경로 1회 | 1/1 | 49초 | 같은 수정 | 같은 계열 |

추가로 고친 점: 같은 공식 사이트의 **다른 언어 문서**(`/javascript/` 등)가 공식 근거로 표시되던 문제예요. 실제로 인용된 적은 없지만, Python 책에서는 인용할 수 없게 막았어요.
데모 기록은 새로 만든 실행(demo3-2)으로 바꿨어요. 7장에서 실제 라이브러리 오류(`NameError`)를 만나고, `getattr` 디버깅 시도가 실행 정책에 막힌 뒤 정상 수정으로 통과하는 과정이 남아 있어요.
비용: 3차 전체 $0.90(잔액 $191.01 → $190.11).

## 4차 — GitHub 책 저장소 감시 → 본문 최신화 → PR

목업 책을 GitHub 저장소 `makepluscode/living-book-demo`(당시 비공개 실험 저장소, 현재 비공개)로 만들고 `drift.watch`로 감시했어요.
책에는 본문 장(1장)을 추가했어요. 설치 명령, "이 책은 LangChain 0.3.25 기준" 같은 버전 문장, 다른 장을 소개하는 문장이 들어 있어요.

| 단계 | 결과 |
|---|---|
| 감지 | PyPI `langchain` 0.3.25 → 1.5.2, `langchain-core` 0.3.61 → 1.8.4 |
| 1장 본문 | 버전 문장·설치 명령 2곳을 **검증한 목표 버전**(1.5.0 / 1.8.1)으로 동기화하고, pip 설치 시도로 확인 · 4장·7장 소개 문장 2곳을 공식 문서 근거로 수정(같은 개정의 4·7장 결과를 맥락으로 전달) · 테스트 모델 문장 1곳은 판단 보류(원문 유지) |

비용: 4장 책 전체 실호출 1회(1장 새 호출) + 감시기 드라이런 1회, 합계 $0.56(잔액 $190.11 → $189.55). 실제 PR은 드라이런 캐시를 재생해서 신규 호출 0건이었어요.

## 한계

- 사례 1개(LangChain 에이전트 API 변경)와 검증 계약 1개로 한 실험이에요. 경로별 표본도 2~4회로 작아요.
- 고정 경로의 Router 비용은 그때 기록하지 않았어요. 전체 비용은 잔액 차이로만 확인했어요.
- 장 점검 평가는 장 3개·27항목, 모두 Python 라이브러리예요. 에이전트는 장마다 1회씩 측정했어요(최종 코드 기준).
