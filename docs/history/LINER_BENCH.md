| 질의 | 결과 수 | Premium | 중앙값 | 범위 | 공식 문서 top3 | 1위 공식 |

| 영어 | 5 | 끔 | 3.03s | 1.30–5.06 | 3/3 | ✅ |
| 영어 | 20 (실제 13) | 끔 | 2.16s | 1.58–2.58 | 3/3 | ✅ |

- 결과 수·Premium 여부는 속도에 의미 있는 차이를 만들지 않았어요(편차가 더 커요). Premium은 이 주제에 추가 데이터가 없어 비용만 2배.
- `max_results: 20`이어도 13개만 반환. `date`는 대부분 비어 있어 "최신성"을 날짜로 판단하기 어려워요.
- 한국어 질의도 1위는 공식 문서지만 top3에 블로그가 섞여요 → **영어 질의 + Premium 끔**이 기본값으로 적절.

## B. Router API (같은 판정 과제, 스트리밍)

| 라우터 | 실제 응답 모델 | 첫 토큰 | 전체 | 판정 | 수정안 | 공식 출처 |
|---|---|---|---|---|---|---|
| liner-claude-router | claude-sonnet-5.5 | 1.3–1.9s | 5.3–6.5s | RED 3/3 | 3/3 | 3/3 |
| liner-gpt-router | gpt-6.1-sol | 3.7–6.3s | 6.9–9.4s | RED 3/3 | 3/3 | 3/3 |
| liner-gemini-router | gemini-3.8-flash | 9.6–11.1s | 10.3–11.8s | RED 3/3 | **0/3 (fix=null)** | 3/3 |
| liner-mark | liner-mark-1.3 | 5.0–6.1s | 6.6–7.9s | RED 3/3 | 3/3 | 3/3 |

- **라우팅이 실제로 동작**: 쉬운 번역 과제는 claude→haiku-5.5, gpt→gpt-6-luna, gemini→3.5-flash-lite로 내려가 1~2초. 어려운 과제만 상위 모델로 가요 → 항목이 수백 개인 원고 점검에서 비용 절감 근거.
- claude-router가 가장 빠르고, 근거 범위를 넘는 부분(`langchain-classic` 경로)을 "근거에서 확인되지 않음"으로 명시. 대신 출력 토큰이 2배(약 700).
- gemini-router는 추론 토큰 920개를 쓰고 매번 `fix: null` → 근거에 코드가 없으면 수정안을 보류하는 보수적 성향. 판정·속도 모두 이 용도엔 불리.
- **근거 없이(검색 미제공) 물어도 4개 모두 RED + 그럴듯한 수정안**을 냈어요. liner-mark는 근거를 안 줬는데도 공식 URL 2개를 `sources`에 적음(실존 URL이지만 검증된 근거가 아님). → 출처는 모델 출력이 아니라 **Search 결과에서만 붙이도록** 파이프라인에서 강제해야 해요.

## C. Agent API (`stream: false`)

| 에이전트 | 시간 | 답변 길이 | 출처 수 | 공식 출처 | langchain-classic 언급 |
|---|---|---|---|---|---|
| Quick Answer | 2.3–5.8s | ~190자 (영어로 응답) | 2–3 | 0–1 | 3/3 |
| Search Agent | 25.6–26.1s | 2,200–3,200자 | 34–51 | 19 | 2/2 |

- Search Agent는 검색 1회+라우터 1회 조합(약 8초)보다 3배 느리지만, **`langchain_classic.chains` 대체 경로와 LCEL 두 가지 수정 방법을 공식 문서 인용으로** 모두 제시 — 라우터 단독이 "근거 없음"으로 보류한 부분까지 찾아냄.
- Quick Answer는 빠르지만 `lang: "ko"`인데 영어로 답했고, 공식 출처가 빠지기도 해요.

## 설계 시사점 (제안, 확정 아님)

1. 기본 경로: **Search(영어, 5개, Premium 끔) → liner-claude-router** — 항목당 약 8초, 공식 출처 3/3.
2. 라우터가 `UNKNOWN`이거나 수정안을 보류한 항목만 **Search Agent로 승격**(건당 $0.02, ~26초). 데모에서 "Liner가 어려운 항목을 더 깊이 찾는" 장면으로 쓸 수 있어요.
3. 출처는 Search/Agent가 돌려준 URL과 대조해 일치하는 것만 표시.
4. 항목 병렬 처리 필요: 순차로 100항목이면 약 13분.
