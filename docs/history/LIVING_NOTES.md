# 개정 흐름(`/living`) 상세 기록

> 2026-11-17~22 초기 2장 목업의 검토·수정 기록이에요. 2026-11-22에 샘플을 실제 출간 도서 7장 구조의 목업으로 바꾸고 에이전트 경로를 추가했어요. 현재 4장 목업과 실행 방법은 [README](../../README.md)와 [AGENT_EXPERIMENTS.md](../AGENT_EXPERIMENTS.md)를 참고해 주세요.

`/living`은 실제 LangChain 에이전트 원고를 책 리비전으로 연결하는 통합 데모예요.
Vivo Books의 **저자 수정 → EPUB 개정 → 최신판 유통·POD** 구상에서,
이번 출품작은 **변경된 장 찾기 → 공식 근거 수집 → 코드·본문 수정 → 실행 검증 → 개정 미리보기**를 맡아요.

```bash
.venv/bin/python -m drift.web --port 8774
# http://127.0.0.1:8774/living

# 웹 없이 한 번에 실행
.venv/bin/python -m drift.living --out out/living/integrated
# → reader.html, original.epub, preview.epub, manuscript.diff, revision.json, events.jsonl

.venv/bin/python -m unittest discover -s tests -v
```

- `sample-book/`: 직접 만든 가상 원고 2장, 책·의존성 매핑, 로컬 릴리스 이벤트, 결정적 테스트 채팅 모델.
- `drift/living.py`: Liner Search로 공식 Python 문서를 수집하고 Router가 코드·본문을 수정해요. 근거가 없으면 Search Agent로 보강해요. 인용 구절이 검색 요약과 일치하고, 수정 예제가 격리 실행에서 기대 출력과 실제 날씨 도구 호출을 모두 만족해야 EPUB 미리보기를 생성해요. 수정안 실행 실패 시 한 번만 재수정해요.
- 원본(책 7장 구조를 본뜬 목업)의 `Tool`·`create_react_agent`·`AgentExecutor`는 설치된 LangChain 목표 환경에서 import 실패. 수정된 `create_agent`/`invoke` 예제는 Seoul·Busan·Jeju 입력에서 응답과 실제 `weather` 호출을 확인했어요. 외부 LLM·날씨 API 응답은 검증 대상이 아니에요.
- 원고는 코드 블록과 표시된 설명 구간만 바꿔요. 관련 없는 4장은 원문 해시와 EPUB 내용까지 동일하게 유지해요. 전체 책 EPUB에 두 장을 모두 넣고, 리더에서 원본·개정본과 근거·검증 이력을 비교해요.
- 캐시는 API 요청 내용·프롬프트·모델의 해시로 구분하며, 화면에 실호출/캐시를 표시해요. 인용이나 실행 검증이 실패하면 수정안을 적용하지 않고 개정 EPUB를 보류해요.
- **구현 범위:** 릴리스 이벤트는 로컬 JSON 재현이에요. GitHub 외부 웹훅·PR·저자 승인·POD·기존 Vivo Books 서비스 배포는 연결 전이에요.

이번에 새로 추가한 코드는 `drift/living.py`, `drift/living_web.html`, 통합 웹 경로, LangChain 샘플과 검증 테스트예요.
기존 이 저장소의 Liner 래퍼·격리 실행기를 재사용했으며, 다른 저장소의 집필 코드·원고를 가져오지 않았어요.
사용자가 제공한 Vivo Books 소개 영상은 새 영상의 상황 설명에만 로컬로 사용하며, 원본을 저장소에 포함하거나 외부 모델에 업로드하지 않았어요.

Grok 재검토를 반영해 불확실한 판정은 Search Agent로 장당 1회 보강하고, 보류 이유를 리더·실행 화면에 구체적으로 표시해요.
인용 대조와 독립 도구 호출 검증은 유지하며, 추가 조사 후에도 미해결이면 원고와 EPUB를 보류해요.
당시 검증 테스트는 43개였어요(2026-11-22 에이전트 테스트 추가 후 51개).

Claude 재검토에서 도구만 직접 호출하는 코드도 기존 검사를 통과하는 빈틈을 확인해 검증을 강화했어요.
이제 실제 `create_agent` 그래프의 `invoke` 결과와 모델에 전달된 `ToolMessage`를 대조하고,
독립 실행에서 도구 응답에 임의 표식을 넣어 최종 답이 그 결과를 사용하는지도 검사해요.
이 검사는 자체 제작 샘플의 `create_agent`/`invoke` 계약을 대상으로 하며 외부 LLM·날씨 API 검증은 아니에요.
캐시만으로 재검증하려면 `.venv/bin/python -m drift.living --offline --out out/living/integrated`를 사용해요.
`--offline`은 캐시가 없으면 유료 API 호출을 거부해요.

리더와 개정 EPUB의 개정 노트에는 관측한 ImportError(변경 이유), 대체 API의 공식 문서 인용,
검색 요약 인용 대조 결과, 코드·설명 변경 위치, 독립 실행 결과, 장별 Markdown·EPUB 해시를 보여줘요.
인용하지 않은 검색 결과는 리더에서 별도로 접어 두며, 원문 페이지 전체를 검증했다고 주장하지 않아요.
에이전트 실행은 세 도시와 도구 응답 변경 확인을 합쳐 4회이며, 실행마다 도구 1회·모델 2회 호출을 검사해요.
`Final Answer:` 접두사 처리는 테스트 모델 전용으로 저자 확인이 필요해요. 후보 검사는 이 샘플의
`create_agent`/`invoke` 계약을 대상으로 하며, 임의의 악성 Python 코드에 대한 완전한 의미 검증은 아니에요.

의도적으로 하네스 내부를 조작하는 공격 코드는 완전히 막지 못해요. 검증 범위는 샘플 계약의 정상 후보와 알려진 우회 회귀이며, 네트워크·홈·키 차단은 별도의 bubblewrap 격리로 유지해요.
리더 첫 화면은 문제·변경 위치·근거·검증·유지·저자 검토 상태를 먼저 보여주고, 상세 이력은 접어서 제공해요.
독자용 EPUB 개정 노트에는 요약·공식 링크·검증 범위를 남기고, 해시·API 호출 시간 등 기술 이력은 리더와 revision.json에서 확인해요.

원본이 정상 실행되는데 Router가 RED(실행 불가)로 판정하면 Search Agent로 최대 한 번 재조사해요.
여전히 모순되면 원문을 유지하고 보류해요. YELLOW 권장 변경은 별도 검증 후 적용할 수 있고, GREEN은 원고를 유지해요.
격리 환경이 없으면 Search·Router 호출 전에 보류해 비용을 쓰지 않아요. Linux 격리 환경이 없는 경우에는
정적 `reader.html` 또는 웹의 ‘이전 검증 결과 보기’로 기록을 확인할 수 있어요. 이는 새 실행 검증이 아니에요.

원본 예제가 추가 import·stream 등 샘플 검증 계약 밖이라 거부되면, 라이브러리 오류라고 판정하지 않고 원문을 유지해요.
원본 실행 시간 초과와 목표 패키지 미설치도 별도 사유로 구분하며 Search·Router 전에 보류해요.
실제 `ImportError`와 검증기의 정책 거부를 구분하는 분류는 원본 실행 딕셔너리 밖에 기록해 기존 캐시를 유지해요.

예외 없이 끝나도 기대 답 대신 `None`처럼 잘못된 값을 출력하면 실제 동작 오류로 분류해요.
출력·독립 입력의 답은 맞고 관측 흐름 검사만 실패한 경우에만 검증 계약 보류로 구분해요.
시간 초과·패키지 미설치 화면은 기존 분기 기록을 재생해 확인했어요.

실제 그래프 인스턴스의 `invoke`를 관측해 Runnable 타입과 LCEL 파이프 합성을 유지하고, `create_agent` 뒤에 남은 구형 `run()` 오류도 숨기지 않아요.
관측한 `invoke`를 거치지 않는 stream 실행 등은 별도 보류하며, 시간 초과 오류는 경고 줄 대신 ‘실행 시간 초과(30초)’로 기록해요. 단일 입력 batch가 관측된 invoke를 호출하고 모든 검사를 통과하면 정상 실행으로 받아들여요.

관측 경계: `with_config(...)`로 만든 그래프 사본이나 동시 다중 입력 batch는 이 샘플의 회차별 관측을 충족하지 못해요.
출력이 맞는 원본은 검증 계약 밖으로 보류해 원문을 유지하고 API를 호출하지 않으며, 수정 후보는 검증 실패로 적용하지 않아요.
현재 샘플 범위는 Claude와 9차례 검토·수정을 거쳤어요.
